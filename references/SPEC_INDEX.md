# 规范索引台账（SPEC_INDEX）

> **这是 Step 0.5「规范装载」的权威入口，动笔前先读这一个文件。**
> 它回答三个问题：`references/` 下有哪些规范？每个规范**必须产出什么**？产出物**由谁校验**？

## 为什么需要这个文件

2026-10-12 三环集团报告事故：13 个规范文件**只读了 3 个**，另外 10 个里的硬规范
（6.1 五类压缩表、独立估值章、风险章三层结构、行业自给率与成本曲线定位…）全部漏做，
而 `check_report.py` 仍报 21 项全绿——因为它匹配的是**字符串**，不是规范。

根因之一是 `references/` 没有**索引**：没有一个地方能让人一眼看出「一共几个文件、还差哪些没读」。
本文件补上这个缺口。**清单行数是可核验的**：`ls references/*.md | wc -l` 的结果
= 下表行数 = **14**（1 个装载索引 + 13 个内容规范）。

## 使用方式（Step 0.5 三步）

```bash
ls references/*.md | wc -l     # 先拿总数（应为 14：本索引 + 13 个内容规范）
```

1. 读本表，拿到全部文件名与强制产出物；
2. **逐个 Read 每个 `.md`**（长文先 `wc -l` 规划顺序），不跳过、不抽样；
3. 在回复里输出装载清单（下表打勾版），本报告不适用的条目写明「不适用 + 理由」。

**判定门禁**：装载清单行数 < 实际文件数 → Step 0.5 未完成，不得进入 Step 3 动笔。

## 无机器校验路径的规范（必须人工逐条对照）

以下内容**没有任何脚本能替你判断**，交付前请人工过一遍：

- `qualitative_discipline.md` 的**卖方自夸打折**与**刷新搬运禁忌**：判断某句话是分析还是转述。
- `moat_framework.md` 的**假护城河清单**（高市占率/优质产品/执行力/管理层）：是否被当成真护城河。
- `forensic_risk_layer.md` 的**判读纪律**：信号 ≠ 判决。异常是「需要解释」，不是「已经造假」。
- `attribution_analysis.md` 的**可修复性分档**：把变化归为「结构性」还是「周期性」是否有据。
- 读者假设自测（`SKILL.md` 「读者假设」节）：让完全不了解这家公司的人只看「核心速览 + 总结」，
  复述「做什么、出了什么事、风险在哪」。讲不出来就是没写清楚。

## 维护约定（新增规范文件时必做）

1. 在本表加一行（#、文件名、强制产出物、落在哪一章、校验方）；
2. 在 `scripts/spec_audit.py` 的 `SPEC_FILES` 字典里**登记该文件**，并尽量加机器检查项；
3. 未登记时 `spec_audit.py` 的**元检查会直接判 FAIL**——这是「规范新增了、执行没跟上」不再复发的机制保证。
