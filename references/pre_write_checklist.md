# 报告写作前清单（check_report.py 硬规则前置）

> **用途**：HTML 报告**动笔前**过一遍，让交付前自检一次通过，省掉「写完 → 自检 19 项 FAIL → 返工三轮」的循环。
> **规则源**：`scripts/check_report.py`（判定逻辑为准）。本文件只做**操作化展开**，不新增规则；
> 与 SKILL.md 冲突时以 SKILL.md 为准。
> **踩坑实例**：2026-09-22 美股 Meta 报告（首轮自检 19 项 FAIL，返工三轮；本清单即由此复盘而来）。

---

## 零、读者假设（2026-09-23 新增，最重要的一条）

**写之前先在心里立一个读者：他第一次听说这家公司，不知道它做什么生意，也未必懂会计。**

报告是为**陌生人**写的，不是为写作者自己、也不是为已经研究过这家公司的内行。由此推出四条硬约束：

| # | 约束 | 反例（禁止） | 正例 |
|---|---|---|---|
| 1 | **术语零假设**：任何英文缩写 / 会计专有名词，首现处必须给「原文英文 + 中文直译 + 本案为何适用」 | 「属 Level 3 主观估值」 | 「Level 3（公允价值第三层级）：以不可观察输入为基础、需重大判断的估值；本案因 Anthropic 未上市、无公开报价而适用」 |
| 2 | **实体零假设**：首次提到任何外部公司 / 机构，必须一句交代"干什么的、和本公司什么关系" | 「CoreWeave 等 neocloud 进入前列」 | 「CoreWeave 等 neocloud（新兴云厂商，以租售 GPU 算力为主，与 AWS 直接竞争）」 |
| 3 | **指代零假设**：不跨段用「其 / 该公司 / 上述业务」当主语；每个数字自带主语与口径 | 「其毛利率同比下降 2pct」 | 「AWS 经营利润率从 38.6% 降至 36.5%」 |
| 4 | **背景零假设**：正文第一节就要能回答"这家公司靠什么赚钱、钱从哪来、看点在哪儿"，让外行读懂后面所有内容 | 开篇直接进财务比率 | 企业概况里先讲清业务与收入结构 |

> **交付前自测**：把报告交给一个完全不了解这家公司的人，让他只看「核心速览 + 总结」，
> 然后复述「这家公司做什么、出了什么事、风险在哪」。他讲不出来，就是没写清楚。

## 一、动笔前先定 10 件事（结构性问题，事后改最贵）

| # | 先定下来 | 不先定的代价 |
|---|---|---|
| 1 | 文件名 `{公司简称}_分析报告_{YYYYMMDD}.html`，日期用 `date +%Y%m%d` 取 | [0] 命名硬匹配；日期写错要改名并同步正文 |
| 2 | 章节骨架（务必含下方 9 张必备章节的**字面词**） | [5] 字面匹配，事后改名要同时动目录 + 锚点 + 正文 |
| 3 | 每个 `<h2 id="sN">` 与目录 `<a href="#sN">` 的一一对应表 | [8] 死链 / 章节漏进目录都判 FAIL |
| 4 | 图表清单（每张图的 `canvas id`） | [3] canvas 与 `getElementById` 必须严格配对，多一个少一个都 FAIL |
| 5 | 每张表的表头列（**数值列记得带 `num-c`**） | [2b] 数值列表头漏 `num-c` 判 FAIL；[2] 列数要一次算对 |
| 6 | 行业地位章节的 3 项信号数据（先查到再写） | [10] 至少命中 3 项，事后补数据等于重写该章 |
| 7 | 定性结论的**出处性质**（哪些是原话、哪些是推断、哪些是判断） | [13] 全文需 ≥3 处出处标记；[12] 定性措辞避开绝对化词 |
| 8 | **本文会出现的专业术语 / 英文缩写清单**，逐个备好「原文 + 中文 + 本案为何适用」 | [14] 高风险术语无定义式说明判 FAIL；[15] 缩写首现未展开会被列出提示 |
| 9 | **财年口径**：财年截止日（X 月 Y 日）＋ FY 标签与日期区间的映射 | [17] 美股报告缺此项判 FAIL。**不先定这个，全文年份会整体错位一年** |
| 10 | **分红与回购表的行/列方向**：左列写指标名、表头写期间（最新期在最左） | [18] 一旦写成「财年做行、指标做列」，整张表要重排；且与全文其他表格方向相反 |

> **动笔时的两条语言纪律**（省掉 [12]/[13] 返工）：① 定性句里**不写「完美 / 必然 / 唯一 / 龙头」等**，要么补数字要么改成有条件表述；
> ② 关键结论句尾**随手带上【源】/【推】/【判】/【疑】**，别等写完再补。
>
> **动笔时的第三条纪律**（省掉 [14]/[15] 返工）：**每写到一个自己"觉得内行都懂"的词，就停下补一句解释**。
> 让你卡壳的往往不是数字，而是这类压缩标签——它们是报告里唯一没人替你兜底的部分。

## 二、逐项硬规则（写的时候就照这个写）

### [0] 文件命名
`{公司简称}_分析报告_{YYYYMMDD}.html` —— 正则 `^(.+?)_分析报告_(\d{8})(?:_v(\d+))?\.(html|md)$`。
日期必须取自 `date +%Y%m%d`，禁止心算。

### [1] HTML 标签闭合
`table / thead / tbody / tfoot / tr / th / td / div / script / h2 / h3 / h4 / footer / nav / canvas / aside`
开闭数量必须逐一相等。**写的时候就配对**，别等自检。

### [2] 表格列数一致
- 判定：`<thead>` 的 `<th>` 个数 == 每个数据行的**视觉列数**。
- **禁止 `colspan`**：脚本按 `<td>` 标签个数统计，不展开 `colspan`，所以 `<td colspan="4">` 只算 1 格，
  汇总行必然 FAIL。**跨列汇总改写为表下方的独立 `<p>` 段落**。
- `rowspan` 是**被正确处理**的（脚本会补占位），可放心用。
- 表格必须有 `<thead>`，否则脚本跳过该表不检查列数（等于放弃保护）。

### [2b] 数值列表头对齐
某列有 ≥50% 的 `<td>` 带 `num-c`，则该列表头 `<th>` 也必须带 `num-c`，否则判 FAIL。
→ 写法：定表头时就把数值列写成 `<th class="num-c">`。

### [3] canvas 与图表注册
- 每个 `<canvas id="X">` 必须有对应的 `getElementById('X')`；反之亦然，不允许孤儿。
- 每个 canvas 必须有 `aria-label`。
- → 先列 canvas id 清单，再逐张写脚本，最后一一 Numbered 核对。

### [4] 时间列排序（强制）
- 含 ≥2 个可识别期间的表头，必须**降序（最新在最左）**。
- 可识别格式：`2025`、`2025年`、`2026H1`、`2026-06-30`、`2026/6/30`、`2026E`。
- **预测年也算期间**：`2025 年 | 2026 年（预测）` 是升序 → FAIL；必须 `2026 年（预测） | 2025 年`。
- 多指标组并列 / 左右双栏（存在重复期间）→ 按重复处分段，逐段各自降序即可。
- 图表 `labels` 若为升序会提示（**瀑布图豁免**，但须在副标题注明）。

### [5] 必备章节（**字面匹配**，改词即失效）

| 必备章节 | 命中任一即可的字面词 |
|---|---|
| 企业概况 | 企业概况 |
| 股权架构 | 股权架构 / 股权结构 |
| 融资与分红 | 融资 / 分红 |
| 核心财务指标 | 核心财务指标 / 财务概要 |
| 资产负债表分析 | 资产负债表 / 简易合并资产负债表 |
| 经营数据分析 | 经营数据分析 / 经营情况 |
| 护城河 | 护城河 |
| 风险预警 | 风险预警 / 风险扫描 |
| 总结 | 总结 |

> 坑：标题写「结论」**不算**「总结」。用「结论与总结」或另起一节。

### [6] 数据来源与免责声明
- 正文须出现「数据来源」或「资料来源」。
- 文末须出现「免责声明」或「不构成…投资建议」。
- 外部联网数据**单列一项**并注明「非公司披露，仅用于交叉验证」。

### [7] 第 0 层硬伤核验痕迹
正文必须出现「审计 / 核数师 / 会计师事务所」之一，并**写明审计意见类型**
（标准无保留 / 保留 / 无法表示意见 / 否定意见）。不得凭印象，须回原文核实。

### [8] 常驻侧边目录（HTML 必做）
五个结构要素缺一不可（脚本逐项检查）：
1. `class="layout"`（栅格容器）
2. `<aside class="sidebar"`
3. `.sidebar { position: sticky }`
4. `class="content"`
5. `.content { min-width: 0 }` —— 否则宽表格撑破栅格

另需：
- 每个 `<a href="#sN">` 有对应 `id`；每个 `<h2 id="X">` 都进了目录。
  - ⚠️ **锚点编号 `sN` 必须是纯数字**（`s0`/`s1`/…/`s12`）。脚本用「数字锚点」正则统计目录条目数，
    写成 `#sT`、`#sTerm` 这类**非数字锚点会被漏统计**，直接报「目录条目数 ≠ h2 章节数」。
  - 增删章节时要**同时**改目录 `href` 与 `<h2 id>`，并**按出现顺序整体重编号**——
    否则会出现 `s1` 与 `s10` 撞车、或两个章节共用同一 `id`（后者脚本不报错，但点击目录会跳错位置）。
- `<header id="top">` 提供「回到顶部」锚点。
- 建议：滚动高亮（`classList.toggle('active'`）。

### [9] 产品用途与客户映射表
`<th>` 中必须出现「工业用途 / 直接客户 / 终端行业 / 下游客户」**任一字面**。
- 消费互联网公司没有「工业用途」→ 表头设计为
  「产品｜是什么（形态）｜用途：解决什么需求｜直接客户（谁付费）｜终端行业（如广告主所属行业）」，
  既过检又不失真。

### [10] 行业地位与竞争格局（独立章节）
- 必须有 `<h2>` 标题含「行业地位」或「竞争格局」。
- 内容须命中下列 **≥3 项**：

| 信号 | 命中关键词 |
|---|---|
| 行业规模 | 市场规模 / 行业规模 |
| 竞争格局 | 竞争对手 / 竞争格局 / 第一梯队 / 第二梯队 |
| 资源自给率 | 自给率 |
| 单位成本 | 完全成本 / 单位成本 / 吨成本 / 成本曲线 |
| 市占率 | 市占率 / 市场份额 / 占全国 / 占全球 |

> 互联网公司拿不到「自给率 / 成本曲线」→ 用「行业规模 + 竞争格局 + 市占率」，
> 且**市占率必须给具体百分比数字**。

### [10.5] 护城河四问与证据链
三项硬检查：
1. **证据表**：`<th>` 含「财报证据 / 量化证据 / 证据链」——每条护城河主张配可验证的量化证据，不足的写「无」。
2. **巨资测试**：须出现「巨资测试 / 巴菲特测试 / 挟巨资 / 10 亿美元 / 100 亿美元」等表述。
3. **章末结论句**：正则要求「护城河」16 字内紧跟（宽阔 / 较深 / 较浅 / 狭窄 / 不存在 / 存疑 / 未发现）。
   → 直接写「**XX 的护城河宽阔**，核心支撑是 …（证据 …），最大威胁是 …」。
   「未发现护城河」也是合格结论。

### [11] 反空值检查（数值列不得留空）
`class` 含 `num-c` 的 `<td>` / `<th>` 内，下列内容一律 FAIL：

```
(空串)   —   -   --   ——   null   N/A   NA   n/a   无   未披露
```

**合法替代写法**（不在黑名单内，且信息量更高）：

| 情形 | 写什么 |
|---|---|
| 同比指标的基准年 | `基准年` |
| 确实无此项 | `0.00`（并在表下说明） |
| 口径不适用 | `不适用（同比指标）` |
| 只在年报披露年度值 | `仅披露年度值` |
| 原始科目确未披露 | 写**具体原因文本**，并在表下注明留空理由 |

> **两个实操要点（2026-09 地平线 09660 实测）**：
> ① 黑名单是**精确等值**匹配，所以「中期公告未单列此口径」「该比例自 2026 上半年起单独披露」
>    这类**具体文本能过**，但直接写「未披露」三字必 FAIL——**别用省略写法，把原因写全**。
> ② 更省事的做法：若某一列**本就以说明性文字为主**（如「更早期口径」「占比变化」），
>    干脆**整列去掉 `num-c`**，把它降级为说明列——`[11]` 只查 `num-c` 单元格，这样既不触发
>    检查、右对齐也不会难看。注意同时确认 `[2b]`：该列 td 的 `num-c` 占比若仍 ≥50%，
>    则表头 `<th>` 必须带 `num-c`（占比降到 <50% 才可去掉表头的 `num-c`）。

> 纪律：**可推算的指标禁止留空**。比率类（毛利率 / 净利率 / 费用率 / 周转率 / 获现率）
> 只要分子分母在报表或附注中存在，就必须逐期算出填上——留空等于掩盖「算一下就行」这个失真动作。

- ⚠️ **分组标题行不要加 `num-c`**。资产负债表里的「资产」「负债及权益」小计分组行，
  其占位格（写 `—` 或留空）**不要带 `class="num-c"`**——脚本只检查带 `num-c` 的格子，
  带上就会被当成「数值列为空」直接 FAIL。分组行只承担视觉分组作用，不参与数值对齐。

### [12] 绝对化词扫描（用词纪律）
写的时候就要避开**营销腔**。规则：`check_report.py` 命中**硬档词**直接 FAIL，**软档词**若无数字/出处支撑则 WARN。

| 档位 | 典型词 | 处理 |
|---|---|---|
| 硬档（禁） | 不可复制、完美、必然、永远、No.1、天下第一、稳赚不赔 | **删掉或改成有条件的表述**，无豁免 |
| 软档（须支撑） | 唯一、垄断、龙头、领先地位、全球第一、行业第一、遥遥领先 | **同行必须出现具体数字**（百分比 / 金额 / 年份）或出处标记，否则 WARN |

- 例外：法律 / 股权语境的「唯一」不算（如「唯一实际控制人」「唯一股东」），脚本已按上下文豁免。
- 改写示例：~~「Meta 的广告技术**完美**领先」~~ → 「Meta 广告技术领先，2025 年广告收入 X 亿美元、市占率 Y%」（**补数字即可**）。
- 常见误伤：**「第一问」「影响最大」「绝对值」不含在软档词内**，可放心使用。
- 详细改写对照与卖方自夸打折纪律见 `references/qualitative_discipline.md`。

### [13] 定性结论出处标注（建议 ≥3 处）
- 定性判断用四分法标记**来源性质**：
  - 【源】= 原文直接表述（财报/公告原话）
  - 【推】= 由数据推断
  - 【判】= 分析者判断
  - 【疑】= 存疑、待验证
- 另可用【公司自述】标注**管理层原话**（需与事实分开）。
- 脚本要求全报告**合计 ≥3 处**，否则 FAIL——目的是让读者一眼分清「哪些是公司说的、哪些是事实、哪些是我的判断」。
- 写作时就在关键结论句尾自然带上，不要事后批量补。
- 完整纪律（含农夫山泉「天然水」案例）见 `references/qualitative_discipline.md`。

### [14] 高风险术语是否给出定义（**读者假设：外行**）
下列术语只要在报告里出现，全文就必须有一处**定义式说明**，否则 FAIL：

```
Level 1 / Level 2 / Level 3 、VIE / 可变利益实体 、KAM / 关键审计事项 、
DLOM 、AOCI 、ASC 820 / ASC 606 / ASC 842 、Non-GAAP 、
净现金转换周期 、剩余履约义务 / 未确认履约义务
```

脚本认可的**三种定义式写法**（任一即可）：

| # | 写法 | 示例 |
|---|---|---|
| ① | 术语 + `：`/`=`/`——` + 实质内容 | `KAM = Key Audit Matter，指审计师…` |
| ② | 术语 + 中文括注（括注 ≥6 字） | `关键审计事项（指审计师须单独披露的最重大事项）` |
| ③ | 「全称（术语）」形式（术语在括号**内**） | `美国会计准则（ASC 820）`、`Amazon.com（AMZN）` |

> ⚠️ **高频陷阱：中文术语 + 短英文缩写括注不成立。**
> `关键审计事项（KAM）` 这种写法**只能让 `KAM` 过关，`关键审计事项` 本身仍然 FAIL**——
> 因为它既不满足②（括注 `KAM` 仅 3 字 < 6），也不满足③（③ 要求术语在括号**内**，此处术语在括号外）。
> 正确写法是把英文全称与中文解释一并塞进括注：
> `关键审计事项（KAM，Key Audit Matter，审计师判断风险最高、须单独向投资者交代的事项）`；
> 同理 `净现金转换周期（CCC）` 应写成
> `净现金转换周期（CCC，Cash Conversion Cycle，存货周转天数＋应收周转天数−应付周转天数）`。
> **判据口诀：中文术语首现处，括注里至少要有 6 个字。**

> ⚠️ **只写中文标签、不给解释 = FAIL**。危险的不是缩写，而是**被压缩过的中文术语**——
> 例如「Level 3 主观估值」，「主观」二字含贬义，读者会误以为在暗示造假，而它其实是个中性会计分类。
> 教训详见 `references/qualitative_discipline.md` 第八节（2026-09-23 Amazon 案）。
>

> ### ⚠️ 术语注解的收录范围（2026-09-24 用户三次收紧后定稿，**当前生效规则**）
>
> **只收「行业专有名词」——即原料、工艺、产品形态等该行业特有的词。
> 会计术语、审计术语、估值比率一律不收。**
>
> | 类别 | 处理 | 例 |
> |---|---|---|
> | **行业专有原料 / 工艺 / 产品形态** | ✅ **唯一收录项** | PET（聚酯瓶片）、NFC（非浓缩还原）、无菌灌装、水源地类型… |
> | 会计计量概念 | ❌ 不收。首现处用一句话就地解释 | FVTPL、Non-IFRS 调整后利润、合约负债、资本负债比率 |
> | 审计概念 | ❌ 不收。首现处用一句话就地解释 | 关键审计事项（KAM）、无保留意见 |
> | 估值 / 经营比率 | ❌ 不收，正文直接用 | 市盈率、市净率、市占率、派息率、净现金转换周期（CCC） |
> | 基础科目与后缀 | ❌ 不收，正文直接用 | 营业收入、毛利率、净利率、归母净利润、HK、LF、TTM |
>
> **为什么会计词改为「就地解释」而不是集中列表**：集中的术语表会随公司复杂度膨胀
> （农夫山泉实测从 20 条一路砍到 2 条），而**读者只在自己读到该词时才会卡住**——
> 把一句话解释放在首现处，既不占篇幅，又恰好在需要的那一刻出现。
>
> #### 「就地解释」的操作要点（与 `[14]` 检查项配合）
>
> `[14]` 仍强制要求 `KAM / 关键审计事项 / 净现金转换周期` 等词**全文有定义式说明**，
> 所以从术语表移除时**必须把这句定义搬到正文首现处**，不能直接删干净。做法：
>
> - **表格行**：在科目名后加中文括注（≥6 字），如
>   `净现金转换周期（CCC，Cash Conversion Cycle，存货周转天数＋应收周转天数−应付周转天数）`
> - **正文句**：首次提到时用括号带出英文全称 + 中文解释，如
>   `关键审计事项（KAM，Key Audit Matter，审计师判定风险最高、须单独向投资者交代的事项）：仅 1 项——…`
> - **段落开头**：以加粗词引出定义，如
>   `<b>Non-IFRS 调整后净利润</b>（Non-IFRS Adjusted Net Profit，非国际财务报告准则调整后净利润）指…`
> - 若某词移出术语表后**在正文中彻底不再出现**（如本案的 `FVTPL`，正文用的是中文全称
>   「按公允价值计入损益的金融资产」），则无需补定义，直接删除即可。
>
> #### 实测边界（农夫山泉案，三轮收紧的完整轨迹）
>
> | 轮次 | 用户要求 | 术语表条数 |
> |---|---|---|
> | 初始 | — | 20 |
> | 第一轮 | 「行业内的专业数据解释保留，通用的删除掉」 | 9 |
> | 第二轮 | 点名删：无保留意见、资本负债比率、合约负债 | 6 |
> | 第三轮 | 「把会计术语解释全部去掉」 | **2（仅 PET、NFC）** |
>
> **当前定稿标准：术语表只应包含行业专有名词，通常 0–5 条即可，会计词条数应为 0。**
>
> - 判据一句话：**「这个词是这家公司所在行业特有的吗？」** 是 → 收；只是会计/金融通用概念 → 不收。
> - **与正文重复的不收**：若「数据来源」或页头标签已说明（如 IFRS／HKFRS、不适用增值税），
>   术语表不再重复列一条。
> - **术语名必须与正文表格实际写法一致**：正文用港式「合约负债」，术语表若保留就不能只写「合同负债」。
> - **删条目时别丢掉其中的公司特定信息**：把它移到相关章节（例：删「归母净利润」条目时，
>   把「本公司无少数股东，故报表净利润＝归母净利润」并入「数据来源」）。

- 免检白名单：`SEC / IPO / CEO / CFO / AI / US / UK / EU / HK / HTML / PDF / Q1–Q4 / H1 H2 / FY / EPS / PE / PB / ROE / ROIC / TTM / EBITDA / GAAP / IFRS / USD / RMB / SaaS / CAGR / GMV / DAU …`
  - `HK` 于 2026-09-23 补入（原白名单有空档：`US/UK/EU` 都在，唯独漏了同为交易所后缀的 `HK`，会对

- 交易所前缀后的代码免检（如 `NASDAQ: AMZN`）。

### [16] 内联脚本跨块重复声明（图表会静默失效）

- 判定：扫描所有 `<script>`（**不带 `src` 的**）块，若同一个 `const` / `let` / `class` 名出现在 ≥2 个块，
  判 FAIL——第二个块会整块 `SyntaxError`，图直接不渲染，而 [3] 的 canvas 配对检查**看不出任何异常**。
- → 写法：`Chart.defaults.color / font` 这类公共初始化**只保留在第一个块**；
  后续块要么不带声明，要么整块用 `(function(){ ... })();` 包起来。
- → 导航脚本**必须独立成块**（见模板骨架），但不重复声明公共变量即可。

### [17] 财年口径标注（**开篇区必写**，2026-09-28 新增）

> **需求来源（用户原话）**：「分析美国上市公司的时候，在最开始标注出『财年』，
> 因为很多公司的财年不是自然年。」

**为什么必须写在最前面**：读者看到 `FY2026` 会默认它是 2026 自然年。但美股公司**可以自选财年截止月份**——
甲骨文截止 **5 月 31 日**，`FY2026` 实际覆盖 **2025-06-01 ~ 2026-05-31**；阿里（港股）截止 3 月 31 日。
不先声明口径，读者会把**每一个年份、每一个同比、每一个估值倍数整体错位一年**，而报告内部完全自洽、
读者也无从自查。这一条的错误成本远高于它占用的版面。

**位置**：`<header>` 内（正文最顶部），或最迟不晚于「核心速览」区块结束——脚本只认
**正文起点 → 第一个编号章节（`<h2 id="s1">`）之前**这个区间。

**写法（三选一，按公司实际情况）**：

| 情形 | 必须写出的内容 |
|---|---|
| 财年 ≠ 自然年（美股最常见） | ① 财年截止日（X 月 Y 日）② 明说「与自然年不一致」③ **FY 标签 ↔ 日期区间映射**（至少给最新一期，写全两期更好） |
| 财年 = 自然年 | 一句话：「本公司财年与自然年一致（1 月 1 日至 12 月 31 日）」；若还用 FY 标签，仍需给一条映射 |
| A 股 | 财年固定自然年，写一句「财年即自然年」即可（脚本对 A 股仅提示不判 FAIL，但建议补齐） |

**正例（甲骨文，报告已采用）**：

```html
<div class="note" style="margin:14px 0 0">
  <b>先看财年口径——不先弄清这一条，后面所有年份都会读错一年。</b>
  Oracle 的财年截止日为每年 <b>5 月 31 日</b>，<b>与自然年不一致</b>。
  本报告中的 <b>FY2026 指 2025 年 6 月 1 日至 2026 年 5 月 31 日</b>；相应地 FY2025 指 2024 年 6 月 1 日至
  2025 年 5 月 31 日，FY2027 Q1 指 2026 年 6 月 1 日至 2026 年 8 月 31 日。全文的年份标签、同比与估值口径均按此定义。
</div>
```

同时在页头 `.meta` 加一枚标签 `<span class="tag">财年截止：每年 5 月 31 日（非自然年）</span>`。

**判定口径（脚本怎么认）**：

1. **财年截止日**：开篇区出现「财年…X 月 Y 日」或「财年…YYYY-MM-DD」（间隔 ≤60 字），
   或「财年与自然年一致」。
2. **FY 标签映射**（仅当全文使用了 `FY20xx` 标签时要求）：标签**之后 150 字内**要同时出现
   明确日期（月日式，或 ISO 起止区间）与连接词（`指 / 即 / 对应 / 截至 / 截止 / 起止 / = / 至 / 到`）。

> **踩坑记录（写检查器时的两次误判，别用更松的写法）**：
> ① 只查「FY 标签附近有没有日期」→ 页头「财务数据源：…FY2022–FY2026…」与
> 「行情数据：2026 年 9 月 25 日收盘」相隔不到 150 字，会被当成已映射；
> ② 把「财年」也算连接词并允许向前取字 → 侧栏目录里的章节名「核心财务**指**标」
> 会贡献一个「指」，与页头的报告日期凑成假命中。**所以开篇区必须先剔除 `<nav>` / `<aside>`（目录）。**

**顺带提醒**：财年非自然年时，「近五年」要以**财年**为单位数（FY2022–FY2026 是五个财年），
不是按日历年份数；同比、CAGR、估值倍数（PE/PB）的年度口径也都随之。

### [18] 分红与回购表版式（**指标为行、期间为列**，2026-09-29 新增）

> **需求来源（用户原话）**：「输出的报告中，『分红与回购』章节，有时候是横向的……有时候又是纵向的，
> 你调整一下输出模板，都调整为后者。」

**唯一合法形态**：左列 = 指标名，表头 = 期间，**最新期在最左**。

```html
<table>
<thead><tr><th>项目</th><th class="num-c">FY2025</th><th class="num-c">FY2024</th><th class="num-c">FY2023</th><th class="num-c">FY2022</th></tr></thead>
<tbody>
<tr><td>每股股息（美元）</td><td class="num-c">3.48</td>…</tr>
<tr><td>股息支付总额</td><td class="num-c">38.05</td>…</tr>
<tr><td>股份回购金额</td><td class="num-c">87.91</td>…</tr>
<tr><td>回购股数（百万股）</td><td class="num-c">56</td>…</tr>
<tr><td>分红 + 回购合计</td><td class="num-c">125.96</td>…</tr>
<tr><td>合计 ÷ 当年净利润</td><td class="num-c">…</td>…</tr>
<tr><td>合计 ÷ 当年经营现金流</td><td class="num-c">89.9%</td>…</tr>
</tbody>
</table>
```

> **末两行的顺序固定**：`合计 ÷ 当年净利润` 在**上**，`合计 ÷ 当年经营现金流` 在**下**。
> 两行的分子都是上一行的「分红 + 回购合计」，只换分母。例：
> FY2025 合计 125.96 亿美元 ÷ 经营现金流 140.12 亿美元 = **89.9%**。
> - `合计 ÷ 当年净利润`——占「账面赚到多少」的比例。净利润含非现金损益（公允价值变动、减值、汇兑），
>   这一行反映的是**分配意愿**，不是现金能力。
> - `合计 ÷ 当年经营现金流`——占「实际收回多少现金」的比例。**这一行才是可持续性的硬约束**，
>   >100% 说明当年回报动用了现金存量或新增借款。两行并列才有信息量。
> - **净利润为负时该行写「不适用（当年净利润为负）」，不得留空或写负比率**（[11] 反空值检查会把留空判 FAIL）。

**判定口径（脚本怎么认）**：在「融资与分红」章节内，某张表的**表头首格**是
`财年 / 年度 / 年份 / 期间 / Year / Period`（可带括号补注），且其后 **≥2 格**是指标名
（命中 `回购 / 分红 / 股息 / 派息 / 股利 / 返还 / 支付率 / 金额 / 股数 / 均价 / 额度 / 现金流`），
**并且其中至少 1 格沾「回购 / 分红 / 股息 / 派息 / 股利 / 返还」** → FAIL。
（最后一个条件是为了不误伤凑巧命中两个宽泛词的表，如 `财年 | 收入 | 净利润 | 经营现金流 | 自由现金流`。）

**禁止形态**：

```html
<!-- ✗ 财年做行、指标做列 -->
<thead><tr><th>财年</th><th class="num-c">股份回购金额</th><th class="num-c">回购股数</th><th class="num-c">每股分红</th><th class="num-c">合计返还</th></tr></thead>
```

**为什么单独立一条**：`[4]`（时间列排序）**抓不到**这种表——横向版的表头里只有「财年」两个字、
没有任何 `20xx` 期间 token，期间数 <2 直接被跳过，所以它能一路通过所有检查。

四条配套纪律：

1. **拆股 / 口径变更另起一行**（如「其中：按 20xx 年 N 拆 1 拆股后口径折算」），不要靠「横向多一列」承载。
2. **指标只有两三个也不退回横向版式**——指标少不是理由，全报告一致性才是。
3. 期间标签用 `FY2025` 或 `2025-12-31` 均可，但**同一章内保持一致**。
4. **4.1 融资表**是事件流水，可保留「时间」为第一列，但行要**自上而下由新到旧**，
   未提用的授信额度等非事件行排在事件行之后。

## 三、收尾（写完立刻做）

```bash
<python> scripts/check_report.py <报告文件.html>
```

- 退出码 0 才可交付；有 FAIL 必须修完再交。
- `--log <file>` 可同时写 UTF-8 日志（绕开 PowerShell 重定向乱码）。

  改用一次性 Python 脚本做字符串替换，每处替换都 `assert 命中次数 == 预期`，改完立刻重跑
  `check_report.py` 验证——比人手逐条改可靠得多。
- 已知豁免：瀑布图等流程型图表的横轴是推导路径而非并列期间，不受「最新在最左」约束，
  但须在图表副标题注明。脚本对图表 X 轴方向只提示不判 FAIL。
