# 经营变动归因分析 — 触发条件与方法

## 何时必做

**收入、毛利、净利润任一同比变动超过 ±10% 时必须做归因**，不得只陈述"下降了 X%"。
低于 ±10% 也要在正文用一句话点明主因。

理由：市场看到"-26.9%"就下结论，而归因往往显示"一条腿瘸了 + 其余分部在对冲"。
这是本报告最容易产生超额认知的一步，**不是可选项**。

## 四件套（缺一不可）

### ① 分部贡献表 — 定位是哪一块

| 分部 | 本期 | 上期 | 变动 | **占净降幅** |
|---|---:|---:|---:|---:|

- `占净降幅 = 该分部变动额 ÷ 合计变动额`（负号 = 形成对冲）
- 单季/半年数据常无上期分部明细 → **用本期披露的同比增速反推上期**，反推后必须加总校验：
  反推值加总与实际合计的尾差应 <0.1%，并在表下注明。
- 关键产出句式：**"净降幅的 122.6% 来自 X 一项，其余 N 个分部合计净贡献 +Y 的对冲"**。

### ② 量价分解 — 拆到驱动因子（仅对有销量披露的分部）

用**连环替代法**：

```
量的影响 = (本期量 − 上期量) × 上期价
价的影响 = (本期价 − 上期价) × 本期量
校验：两者之和 ≈ 收入变动额（尾差注明）
```

- 均价为推算值时（= 分部收入 ÷ 销量）必须在表下注明"推算"。
- 必须判断：**量跌和价跌的性质不同**——量跌通常指向需求/份额/节奏，价跌通常指向行业周期/成本传导。

### ③ 归因瀑布图 — 一图看全貌

用 Chart.js floating bar（`data: [[min,max], ...]`），起点=上期、终点=本期，中间按分部依次步进。
每根柱子单独着色（增=绿，降=红）。**瀑布图豁免「最新在最左」规则**（流程型图表），需在副标题注明。

### ④ 可修复性排序表 — 最关键的一张

把各原因按性质分四档，直接回答"这个变动明天还在不在"：

| 原因 | 性质 | 是否会修复 | 依据 |
|---|---|---|---|
| 抢运高基数 / 主动去库存 | 节奏性 | **会** | 存货已去化 X 亿，基数效应自下半年消退 |
| 行业价格下行 | 周期性 | 部分 | 下季供给预计减产至 X |
| 新规过渡期发运延后 | 一次性 | **Q3 起修复** | 过渡期至 X 月 X 日止 |
| 渠道禁售 / 牌照上限 | 结构性 | **不修复** | 永久性制度约束 |

- 最后必须给**量化结论**："-26.9% 里约七成是会修复的节奏/价格因素，三成是结构性约束"。
- 并明确指出**需要下一份财报验证的是什么**（如：下滑中有多少属永久性份额丢失）。

## 外部交叉验证（必做）

**当归因涉及宏观/行业变量时必须联网验证，不能只凭财报自述。**公司管理层给的原因往往是笼统的
（如"国际贸易关系及发运节奏"），只有外部数据能把它坐实或推翻。

典型验证路径：

| 归因类型 | 该查什么 |
|---|---|
| 售价下跌 | 行业供需报告（产量/供给同比、产区均价）、大宗商品指数 |
| 销量下滑 | 行业出口数据、海关口径、行业协会月度综述 |
| 政策影响 | 监管原文公告（**必须读原文条款**，第三方转载常漏关键条目与过渡期安排） |
| 汇率 | 相关币种半年走势 |

**外部数据标注规则**：
- 表格/正文内联处注明来源；
- 文末数据来源单列一项（如"③ 外部交叉验证数据：xxx，非公司披露内容，仅用于交叉验证"），
  **与公司披露的一手数据严格区分**；
- 外部数据只能用于**解释**，不得用于替代公司披露数据。

## 常见陷阱

1. **只看总收入不看结构**：占比变化造成的"结构性幻觉"（详见风险优先级 #6）会让毛利率、费用率失真。
2. **把公司的自述当结论**：管理层口径常把多个原因并列，需拆出主次并量化。
3. **漏掉"永久 vs 一次性"**：这是归因最有价值的部分，决定要不要调整长期判断。
4. **反推上期数据不校验**：加总平不了就是反推错了。
5. **只归因不验证**：跨过这一步，归因就只是复述公告，没有增量。
